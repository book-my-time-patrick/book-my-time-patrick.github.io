# M2 邮箱与预约申请

后台增加「预约申请」和「邮箱设置」。受邀者可切换周历、点选时间或用表单选择日期、开始时间和时长。预约申请提交后进入待确认列表。开启收件后，送达邮箱会收到附暂定 `.ics` 的申请邮件，回复地址是申请人邮箱。可在后台或邮件链接中确认、拒绝、建议其他时间。

## 预览流程

1. 用通行密钥进入 [管理后台](https://book-my-time-patrick.cn/#/admin)。在「邀请链接」创建预览，勾选「预约日历」和「申请时间」。
2. 打开预览，切换周历，选一个未来的工作日时段，检查选中的日期、时间和时长是否同步到申请表。手机端用日期横条查看当天时段。
3. 当前周标明今天，已经过去的时间统一置灰。显示范围为 UTC+8 的 09:00–21:00，周一至周五可申请。支持 30、60、90、120 分钟，最远可申请未来 30 天的时段。已过期和不可申请的时段不可点选。

M2 周历显示申请规则。真实忙闲来自后续的 iCloud 和 Outlook 接入。可申请的时段需要人工确认，提交申请本身不占位。系统在确认时检查已确认预约的重叠。预览只提供试选和表单查看。

## 启用真实邮件

1. 注册 [Resend](https://resend.com/signup) 的 Free 套餐。免费额度为每天 100 封、每月 3,000 封。项目的收件限制按低量私人预约设置。[Resend 套餐](https://resend.com/pricing)
2. 在 Resend 的 Domains 添加 `notify.book-my-time-patrick.cn`，按页面提供的具体名称和值，在 Cloudflare 的 DNS Records 添加发件子域的 SPF 和 DKIM 记录，等待 Resend 显示 Verified。发件子域关闭邮件打开和链接点击追踪，供预约事务邮件使用。可按官方说明核对该子域的 DMARC。[验证发件域名](https://resend.com/docs/dashboard/domains/introduction) · [配置 DMARC](https://resend.com/docs/dashboard/domains/dmarc)
3. 在 Resend 的 API Keys 创建仅发信用的密钥。在后台「邮箱设置」填写 `bookings@notify.book-my-time-patrick.cn` 和密钥并保存。密钥由服务端加密保存，后台只显示配置状态。[Resend API 密钥](https://resend.com/docs/dashboard/api-keys/introduction)
4. 在「邮箱设置」添加自己的收件地址，发送验证码，然后填入邮件里的六位数字。选一个已验证的邮箱作为主送达邮箱。通知邮箱可设为同一个，也可另外选择；可按邀请指定不同的已验证送达邮箱。
5. 点击「发送测试 .ics」，在实际使用的邮箱中检查是否收到，以及手机日历是否能打开附件。随后开启「接受预约申请」，使用新的普通邀请做一次完整的申请和审批。

邮箱配置变更、发验证码和测试邮件要求近期通行密钥验证。通过邮件链接处理预约时，打开链接先显示内容，点击操作按钮后才写入状态。链接仅可处理对应待确认申请一次，到申请时段开始时失效。建议其他时间的邮件会邀请对方回复，建议本身不占位。

## 处理邮件异常

「预约申请」中的邮件状态反映发信服务是否接受消息。实际到达时间与收件邮箱有关。服务拒绝或连接中断时，申请和审批结果仍保存在后台，可在列表里重试发信。发信重试使用同一操作的标识避免重复发送。首次发送超过 23 小时仍无法确认时，先在 Resend 邮件记录中核对是否已发送，再用邮箱手动联系对方。

发信路由按发送时的邮箱设置选择。如果更换主送达邮箱，已经导入到旧邮箱关联日历的项目需要在原日历中核对。

## 部署与验收

部署前应用 `0004_booking_requests.sql` 和 `0005_mail.sql`。本机测试使用合成数据与模拟发信服务，可以验证验证码、附件、回复地址、失败重试、一次性邮件操作及冲突审批。实际邮箱送达和手机日历打开附件须在完成以上配置后验证。

2026 年 11 月 6 日已发布到正式 Worker 版本 `3c586b99-ffe5-4c70-866c-a718f3ab7aa8`。本机 35 项测试通过，另在本机 Workers 运行时和临时 D1 完成 20 项模拟发信流程检查。正式站点的 19 项资源与接口权限检查通过。隔离云端的完整流程遇到网络中断，临时路由、Worker 和数据库均已清理。可用 `npm run probe:m1 -- --m2` 复验。正式站点初始关闭真实申请，管理员可先预览周历和表单。
