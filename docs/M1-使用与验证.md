# M1 使用与验证

本轮交付范围是后台认证、登录设备与通行密钥管理、邀请链接、服务端门禁及受邀者预览。首版 M1 已发布，历史 Worker 版本为 `0ffb75f1-4707-449b-97ca-f78754f9a8b4`。正式管理员已完成首次绑定，当前更新保留现有管理员与凭据；完整真实设备验收尚未完成。

## 通行密钥登录更新 · 2026 年 11 月 6 日

日常登录与敏感操作的近期认证改为只验证通行密钥，不再输入网站六位动态码。服务端仍完整验证挑战、签名、Origin、RP 与用户验证标记；操作系统可提供 Touch ID、Face ID、Windows Hello 或设备 PIN 等方式，网站不能强制只用生物识别。

勾选记住的有效会话在同一浏览器内最长保留六个自然月。关闭页面后再打开可直接返回后台；点击「退出登录」会撤销当前会话，下次需要重新使用通行密钥。

首次绑定仍要求独立初始化码、二维码/TOTP 与通行密钥，流程改为扫码后先保存通行密钥，再输入最新动态码，避免系统保存窗口占用动态码有效时间。动态码错误可在同一未过期流程内重试，不必重新扫码；挑战五分钟有效期不延长，重试继续受限流约束。页面提供可复制的错误代码、HTTP 状态、阶段与 Cloudflare Ray ID，不包含动态码、设置密钥、挑战或凭据响应。

当前本机 27 项自动测试、TypeScript 检查、主站构建及 Worker 打包通过。新的免费 Workers 隔离云端探针 29 项通过，包含不传动态码的登录与近期认证，临时路由、Worker 和 D1 已删除。正式 Worker 版本为 `b2734358-8d1a-4f84-acb7-1b68c9d0f012`，线上静态资源、API 与已有管理员状态的 12 项检查通过，记录在本机 `.local/passkey-login-production-check.json`。真实 Chrome、iPhone、Windows 等系统界面的新流程仍待实机验证；已有成功绑定不需要重做初始化。

该轮历史版本为 `fa627a70-764e-4abb-9fd3-b6e8250cab1f`。首次设置显示浏览器本地生成的二维码，可在 Microsoft Authenticator 中添加「其他账户」并扫码，手动添加方式保留在可展开区域。完成服务端绑定且会话确认成功后显示「绑定成功」弹窗；已保存绑定但确认暂时断网时提供重连，避免重复初始化。

## 第一次设置

正式管理员已经完成首次绑定，不要重新初始化。以下步骤仅用于尚未创建管理员的独立数据库，必须由本人执行：

1. 在当前电脑打开 `.local/m1-首次初始化.txt`，复制其中的初始化码。不要将整个文件转发给别人。
2. 用自己的浏览器打开主站后台，在初始化表单单独输入该码。
3. 准备支持基于时间六位动态码的身份验证器，添加「其他账户」并扫描后台显示的二维码；同机操作或无法扫码时，可展开手动方式填写设置密钥，账户名称可写「受邀预约」。
4. 选择是否记住这台设备，按系统提示创建并保存通行密钥，完成系统提供的验证。
5. 返回页面后，再输入刚才添加的验证器账户里的最新六位动态码。服务端确认绑定和管理会话成功后弹出「绑定成功」，点击「进入后台」继续。
6. 建议尽早在另一台常用设备或独立保存位置添加第二把通行密钥，并保留验证器的安全备份。

初始化码是 256 位随机授权码，生成后 24 小时到期，不是以后要记住的密码。单次绑定挑战有效五分钟；动态码错误时可在原流程内输入最新码重试，重试受限流约束且不延长原有效期。超过五分钟重新开始，页面会生成新的验证器设置密钥，应使用新密钥完成本次绑定。结果暂时无法确认时，先按页面提示重连检查，不要重复扫码。

服务端同时验证初始化码、有效期、通行密钥完整响应和 TOTP。创建唯一管理员后，首次初始化入口永久关闭；旧码或后来重发的码都不能再次创建管理员。工具不会替本人创建正式管理员。

二维码由浏览器本地生成；二维码与设置密钥只在这次绑定页面显示，不发送到外部二维码网站。复制的验证器链接含密钥，同样属于秘密。不要放进聊天、公开文档或 Git。

## 日常登录

无需输入账号、记忆密码或网站六位动态码。点击「使用通行密钥登录」，完成系统验证即可。手机、Mac 和 Windows 的保存方式由操作系统、浏览器与选定的凭据保存位置决定，网站只保存公钥，不接收人脸、指纹或设备解锁 PIN。Face ID、Touch ID 是否可用由系统决定，系统也可能要求设备 PIN 或解锁密码；网站不能强制只使用生物识别。

新设备须能调用此前已注册的通行密钥，例如由支持的密码管理器同步或通过系统提供的跨设备验证使用；也可以在已登录的后台授权添加新密钥。陌生设备上任意人完成自己的 Face ID 或指纹，并不会获得后台权限。

| 会话选项 | 期限 |
| --- | --- |
| 勾选「记住这台设备」 | 最长 6 个自然月 |
| 未勾选 | 12 小时 |
| 敏感操作的近期验证 | 最近 10 分钟内完成通行密钥验证，无需动态码 |

会话在服务端保存哈希，通过 HttpOnly、Secure、SameSite=Strict 的主站 Cookie 使用。同一浏览器有效会话内日常页面只核验会话，关闭标签页或浏览器后重新打开无需再次验证。点击「退出登录」会立即撤销当前会话并清除 Cookie；到期、被撤销或清除 Cookie 后也需要重新使用通行密钥。不同浏览器不共用这份登录状态。

每次通行密钥验证使用一次性挑战，已完成、错误或过期的登录挑战不能重复提交。首次绑定的动态码只在该绑定流程内使用；日常登录和敏感操作不再检查 TOTP，因此不需要等待下一组动态码。

本版没有通过动态码单独登录或找回账户的通道，也没有网页自助恢复流程。失去全部可用通行密钥时，先保留仍有效的会话和正确备份，由维护者评估恢复；TOTP 和重发初始化码不能绕过已有管理员。

## 登录设备与通行密钥

### 登录设备

「登录设备」按浏览器会话显示：昵称、粗粒度系统和浏览器、首次登录、最近使用、到期时间及当前设备标记。同一电脑的不同浏览器可能显示为不同登录。系统标签不使用硬件指纹；部分浏览器不能准确区分 Windows 10 与 11，列表可显示合并标签。

可以改昵称、移除某个登录、退出其他全部登录。移除当前登录会回到登录页。服务端立即拒绝被撤销会话的后续请求；后台收到失效响应后清除当前显示的管理数据。已经打开且暂未发请求的页面，要在下一次校验时获知变化。

### 通行密钥

通行密钥是凭据，登录设备是会话，两者分开管理。支持添加、命名和撤销凭据；新增或撤销等敏感操作需要近期通行密钥验证，无需输入动态码。服务端原子保护最后一把凭据，不能删到没有有效通行密钥。

撤销凭据会使它关联的会话失效。若某把通行密钥通过系统服务同步到多个设备，撤销的是本站这把凭据，其所有副本都不能再用于本站；移除一个浏览器登录则不会删除其他设备共用的凭据。

iPhone、Mac、Windows 10 与 Windows 11 仍需分别实机确认系统保存、扫码及重新登录路径。不能用合成认证器或某一个系统的界面代替其他设备验收。

## 邀请链接

创建邀请时填写备注、有效期、可见模块和允许的预约方式。备注只在后台使用，不向受邀者返回。M1 当前权限用于服务端门禁与准备中模块裁剪，后续真实功能仍按里程碑交付。

每条邀请的原始令牌为 256 位随机数，服务端数据库只存 SHA-256 哈希。原始链接只在创建、复制为新链接或预览的响应中提供；后台页面在内存中保留供复制，不存进浏览器持久化存储。

生成后及时复制并保存到自己可控的位置。刷新、离开或退出后台后，页面内存会清空，不能从数据库找回旧令牌。「复制为新链接」创建另一条独立邀请，原邀请仍保持自己的有效期和状态。

可以延期、修改权限或撤销。新状态立即在服务端后续校验中生效；无效、过期和撤销的访客提示统一，不泄漏历史存在状态。当前已经加载的准备页面不代表后续请求仍被授权。

邀请令牌位于 `#` 后，通过 Authorization 请求头交给 API，不进入服务器 URL 路径和常规 Referer。分享时保留完整链接，并避免公开转发。

### 以受邀者视角预览

后台可按当前权限或已有邀请设置生成临时预览。预览有效一小时，页面带醒目提示，不计入邀请访问次数，不创建预约，不发送邮件。临时预览不出现在普通邀请列表中，到期后服务端拒绝继续使用。

## 准备与部署

在项目目录使用 Node.js 22.12 以上版本。首次获取代码后先安装依赖：

```bash
npm ci
```

### 本机开发

```bash
npm run prepare:local
npm run dev
```

打开 `http://127.0.0.1:5173/#/admin`，从 `.local/m1-local-首次初始化.txt` 读取本机初始化码。Wrangler 本机 D1、正式 D1 和 Node SQLite 是独立数据库，测试管理员不会自动迁移。

`prepare:local` 应用本机迁移并准备 `.dev.vars`、`.local/node-secrets.env` 和本机秘密备份。重复运行保留现有加密密钥。尚未初始化且码过期时：

```bash
npm run prepare:local -- --refresh-setup
```

### 正式主站

确认当前电脑已完成官方 Cloudflare 授权，运行：

```bash
npm run configure:worker -- https://book-my-time-patrick.github.io https://api.book-my-time-patrick.cn https://book-my-time-patrick.cn
npm run prepare:m1
npm run deploy:site
```

配置脚本保留已有 D1 绑定，也允许显式提供第四个数据库 ID 参数；普通更新不需要填写。`prepare:m1` 创建或复用正式 D1 并应用迁移，把密钥作为 Worker secrets 设置。当前使用免费套餐，不自动升级。

主站构建写入 `.local/site-dist/`，强制 API 为 `/api`。GitHub Actions 仍只发布备用 Pages 到 `dist/`。以后无数据库结构变更的主站更新运行 `npm run deploy:site`；有新增迁移时，先运行 `npm run prepare:m1`。

未创建管理员且初始化码过期时：

```bash
npm run prepare:m1 -- --refresh-setup
npm run deploy:site
```

这只更换首次初始化授权，不会删除用户、重置验证器或重新开放已关闭的注册入口。

秘密和初始化文件按 `0600` 写入，仅当前系统用户可读写，均排除 Git。初始化码先在本机持久化，再进行可能失败的远程操作，便于中断恢复；实际可用仍以迁移、secrets 和发布均成功为准。

`DATA_ENCRYPTION_KEY` 用于加密数据库中的 TOTP 种子，必须稳定保留。重复准备不会覆盖已存在的线上加密密钥；若线上有密钥而本机备份丢失，脚本会停止并要求恢复备份。不要自行删除或轮换加密密钥，当前没有在线密钥轮换功能。

安全保存数据库及对应密钥备份。数据库备份本身不能替代加密密钥，只有密钥也不能恢复数据库里的会话、邀请和管理员记录。正式备份恢复流程尚待单独验收。

### Cloudflare 自动抓取规则待修正

正式检查发现 Cloudflare 在本站 `Disallow: /` 前自动添加了托管抓取规则，包含 `Allow: /`，因此未将此项判为通过。本站静态 HTML 和 HTTP 响应仍带 noindex，个人数据仍由服务端鉴权；平台改写需要另行关闭。

现有 Wrangler 授权调用 Bot Management 更新接口返回 403，不能用该工具关闭。用户需进入域名的 **Security → Settings → Bot traffic → AI Crawler and Agent access policies**，关闭 **Enable Bot Preference Sync** 后保存；旧版名称为 Managed robots.txt 时也关闭自动管理，然后重新检查线上文件与本站文件一致。依据 [Cloudflare 官方说明](https://developers.cloudflare.com/bots/additional-configurations/managed-robots-txt/)，不能用更换 Worker 路由冒充已关闭该功能。

## Node + SQLite 备用

Node 使用同一套 API 和 SQLite 适配，当前迁移在启动时幂等执行。默认数据库 `.local/app.sqlite`，可用 `DATABASE_PATH` 指向持久目录。正式切换前需恢复正确数据与加密密钥，并验证新站点 Origin、HTTPS 和通行密钥行为。

本机 HTTP 示例：

```bash
npm run prepare:local
cp .env.example .env
npm run build
node --env-file=.env --env-file=.local/node-secrets.env build/server.js
```

打开 `http://127.0.0.1:3000/#/admin`，从本机开发初始化文件单独输入码。`.env` 提供本机地址等设置，第二份环境文件提供密钥；不要把真实值填回 `.env.example`。

Docker 配置保留 SQLite 数据卷和 Caddy 证书卷，但尚未实际运行。HTTPS 反向代理需要显式 `TRUST_PROXY=1`；Node 只在原请求 Host 与 HTTPS 站点完全匹配、且代理协议为 HTTPS 时恢复请求协议，不读取任意 X-Forwarded-Host。Compose 已启用该选项，应用端口仅供内部代理访问；普通环境默认关闭。反向代理后的 HTTPS、Origin 校验与恢复链路仍需实测。未验证这些条件前，不把 Docker 配置视为已经验收的正式备用站。

## 常见问题

| 表现 | 处理 |
| --- | --- |
| 后台提示尚未初始化 | 使用单独保管的对应初始化码；链接本身不授权注册 |
| 初始化码过期 | 仅尚未创建管理员时重发；不能用于重置已有管理员 |
| 首次绑定动态码拒绝 | 使用刚扫码添加的账户里的最新码，确认设备时间自动同步；原流程未过期时无需重新扫码 |
| 系统验证取消 | 重试即可；若超时导致挑战失效，重新开始流程 |
| 敏感操作要求再验证 | 完成通行密钥系统验证后重试，无需输入动态码 |
| 退出后再次要求登录 | 退出会立即结束当前会话；需保持登录时直接关闭页面 |
| 系统验证后仍失败 | 选择此前成功绑定的密钥；保留页面的错误代码、状态、阶段与 Ray ID，勿提供验证码或密钥 |
| 无法撤销最后一把密钥 | 先添加另一把有效凭据 |
| 刷新后找不到原邀请链接 | 数据库只有哈希，使用自己已保存的链接，或复制为新邀请 |
| 管理服务暂不可用 | 检查 D1 绑定、迁移、主站源和服务端密钥，失败时保持关闭 |
| 移动网络可开但 Wi-Fi 不可开 | 保留浏览器错误提示，换另一条实际 Wi-Fi 对照；不能直接认定原因 |

M0 的 Wi-Fi 覆盖仍待补，具体运营商、终端和逐项反馈只保存在本机。这里不公开测试网络细节、初始化码、令牌或真实日历数据。
