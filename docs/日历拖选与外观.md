# 日历拖选与两套外观

邀请页的预约日历现在支持：**拖动选择时间段**、**两套可切换外观（紧凑 / 苹果）**、**浅色与深色**，并调整了桌面与手机的布局。预约规则、接口和提交流程没有变。

## 外观

日历卡片右上角有三个按钮：`紧凑`、`苹果`、`◐`（深浅色）。选择只保存在当前浏览器（`localStorage` 的 `booking-skin`、`booking-scheme`），不会上传。默认是「紧凑」，深浅色跟随系统，点 `◐` 后固定为浅色或深色。

| | 紧凑（方案 C） | 苹果（方案 B） |
| --- | --- | --- |
| 可约时段 | 绿色块 | 留白，悬停提示 |
| 已占用 | 斜纹 | 灰色块 + 左色条 + “已占用” |
| 行高（30 分钟） | 16px | 22px |
| 主色 | 站点蓝 | 苹果蓝 |

两套外观共用同一份页面结构，只换 CSS 变量，所以切换不会重新请求数据，也不影响已选时间。开放局用四种颜色的半透明底加左色条，两套外观一致；红色“现在”线显示当前时间。

## 拖动选择

选中的时间由「起点 + 时长」决定，拖动只是更快地得到这两个值。

- **鼠标**：在可约时段上按住并上下拖动，松开后选定。选中块的上下边缘各有一个圆点手柄，拖动可以调整起点或终点。
- **手指**：**长按约 0.25 秒后再滑动**才进入选择（手机会轻微震动提示）；平时的上下滑动仍然滚动页面。选中块的手柄不需要长按，按住就能拖。
- **单击/轻点**：行为和以前完全一样，选起点并沿用当前时长。
- **Esc** 取消正在进行的拖动。拖动时有提示框显示 `13:00–14:30 · 90 分钟`。

### 范围怎么算
拖动范围是「起点所在行到指针所在行」，两端都包含。结果一定是服务端允许的：

1. 只覆盖可选的行。遇到占用（直接预约模式）、开放局或不可约的行，就停在它前面。
2. 总时长必须在该起点允许的时长里（后台“预约规则”里的 30/60/90/120 等，以及每个时段自己的可用时长）。超过最长时长就回缩到允许的最长范围。
3. 向上拖时，起点上移，结束时间不变。
4. 手指刚按下、还没移动时，沿用当前时长；一旦移动，回到起点那一行就表示“恰好一行”。

这部分是纯函数，在 `web/src/booking-drag.ts`，由 `tests/booking-drag.test.ts` 覆盖。

## 手机上的设计：滚动和选择怎么不打架

手机上最大的矛盾是：日历占了大半屏，手指在上面既要滚动页面，又要拖选时间。

**采用的方案：长按进入选择，手柄专管微调**
- 日历区域始终允许竖向滚动，没有“滚动死区”。普通滑动、惯性滚动不受影响。
- 只有按住不动约 0.25 秒才进入选择模式，这时页面不再跟着手指滚动，直到松开。这和苹果日历“长按新建”的习惯一致。
- 选中后，边缘的圆点手柄是专门的小热区，按住就能拖，用来精调，不需要再长按。
- 允许的最长时长只有约 2 小时，拖动范围很小，所以不需要“拖到屏幕边缘自动滚动”。
- 日历顶部和底部提示文案会说明“长按后上下滑动”，避免不知道怎么用。

**没有采用的方案：专门预留一条滚动带**
一周 7 列在手机上每列只有约 48px，没有多余宽度可以划出一条专用滚动区；预留了反而让整个日历都不好选。长按方案不占任何空间。

**配套的手机布局**
- 手机的周视图改为 7 列紧凑网格（原来是按天列出的概览列表），这样才能在周视图里直接拖选。默认仍是日视图，每行 44px，更适合手指。
- 表单变成**底部抽屉**：折叠时只显示一条摘要（所选时间 + “填写申请”），点开后填写，提交按钮吸附在抽屉底部。`Esc` 或再点一次收起。
- 桌面（>900px）表单在日历右侧，选完时间直接填写，不再需要滚动。

## 已知限制
- **键盘**：拖动是鼠标/触摸的增强。键盘用户仍然用 Enter/空格选起点，并用「开始时间」「时长」下拉调整，这些控件都保留着。手柄对读屏器隐藏。
- **没有在真机上验证**：iOS Safari、安卓 Chrome 的长按、震动、阻止页面滚动等表现，只在桌面 Chrome 的触摸模拟下验证过。尤其是 iOS 的长按菜单和文字选择，已用 CSS 关闭，但需要在真机上确认。
- 手机的周视图不再显示每日一行的概览条。如果你更想保留它，可以做成视图里的第三个选项。

## 验证记录
- 自动化：`npm run check`、`npm test`（含 8 项拖选逻辑测试）、两种构建通过。
- 在真实接口加内存数据库上用 Chrome 脚本驱动：鼠标拖选 14 项、触摸模拟 13 项（长按滑动、滑动滚动不误选、长按不动、手柄、抽屉）、直接预约模式下占用块的限制，均通过。
- 生产构建带严格内容安全策略（`style-src 'self'`）运行，拖选、提示框、外观切换无任何违规报错。位置等动态样式全部通过脚本设置，没有行内 `style` 属性。
