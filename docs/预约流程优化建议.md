# 预约流程优化建议

本文只提建议，**没有改动任何代码**。每条标明改动性质：

- 【纯视觉】只改 CSS 或排版，不动 JS 逻辑、接口和数据；
- 【小改标记】改少量 HTML 结构，逻辑不变；
- 【改逻辑】会动交互流程或状态管理，需要你确认后再做，并补测试。

你要求只改视觉、不动整体框架和逻辑，所以我默认只落地【纯视觉】和【小改标记】两类；【改逻辑】的项目只在这里列出，等你确认再做。

## 现状：受邀者从打开链接到提交

调研基于 `web/src/invitation.ts` 与 `web/src/invitation-booking.ts`（`main` 当前版本）。

1. 打开 `#/i/<token>`，先看到“仅限受邀访问”门禁页，再变成“正在确认你的邀请…”，然后才出现页面。
2. 页面顶部是一块较大的欢迎区（标题、有效期说明），日历在其下方。
3. 日历默认周视图（手机默认日视图），先显示“正在读取周历…”，再出现网格。
4. 点一个空闲时段后，日历下方出现一个“已选择”提示条和“填写申请 ↓”按钮；表单在**另一张卡片**里，需要滚动过去。
5. 表单里“日期 / 开始时间 / 时长”三个下拉与日历选择重复。
6. 若同时允许“邮件申请”和“直接预约”，在选时间之前就要先选模式。
7. 提交后表单被回执替换，没有“再约一个”或“加入日历”的入口（开放局有 `.ics`）。
8. 手机上周视图是 7 行列表，要先点某一天进入日视图，再点时段，再滚到表单，至少 3 次点按。

## 摩擦点与建议

| # | 摩擦 | 建议 | 性质 |
| --- | --- | --- | --- |
| 1 | 选时段和表单分在两张卡，靠“填写申请 ↓”连接 | 桌面端把表单做成日历右侧固定面板，选中时段立即带入；手机端用底部抽屉（折叠时显示已选时段 + “填写申请”）。参见 `prompt/` 的方案 A、B、C | 【小改标记】+【纯视觉】 |
| 2 | 日期/开始/时长三个下拉与日历重复 | 保留但缩小，作为微调入口；时长改为分段按钮（30/60/90/120），已选时段显示成一张摘要卡 | 【纯视觉】 |
| 3 | 欢迎区过高，日历被压到首屏以下 | 欢迎区压成一行（称呼 + 有效期），内边距从约 62px 降到约 16px | 【纯视觉】 |
| 4 | 门禁页闪现，像是访问被拒 | 邀请路由在加载期间直接显示日历骨架（灰色周网格），不再先画“仅限受邀访问” | 【改逻辑】（`main.ts` 路由顺序） |
| 5 | 先选模式再选时间 | 把模式开关挪到选完时间之后，放在提交按钮上方 | 【改逻辑】 |
| 6 | 手机周视图是列表，要 3 次点按 | 手机直接用 7 列紧凑周历（方案 C 的 390px 版），点一格即选中并弹出抽屉；日视图保留为放大模式 | 【小改标记】+【纯视觉】 |
| 7 | 提交后无后续动作 | 回执里加“加入日历（.ics）”与“再约一个”；请求模式至少提示“确认后会邮件通知你” | 【改逻辑】 |
| 8 | 请求模式看不到忙闲 | 请求模式也可以用斜纹弱化明显已占用的时段（需要接口返回忙闲）。这涉及隐私规则，默认不做 | 【改逻辑】 |
| 9 | 提交按钮文案分散 | 统一为一个主按钮（“提交申请”/“确认预约”），“复制申请文字”降为次要图标按钮 | 【纯视觉】 |
| 10 | 表单字段多 | 姓名、邮箱同一行（宽屏）；会面方式（线上/线下）折叠到“更多”，备注默认一行高 | 【小改标记】 |

## 建议的落地顺序

1. 先选定视觉方案（见 `prompt/README.md`）。
2. 落地第一批【纯视觉】：槽高、字号、内边距、配色、斜纹、选中态、按钮样式（条目 2、3、9）。
3. 第二批【小改标记】：两栏容器、右侧面板/手机抽屉、紧凑手机周历（条目 1、6、10）。
4. 单独评审【改逻辑】项（4、5、7、8），每项都补测试后再合并。

## 需要你决定的

- 要不要在手机上用底部抽屉（方案 C）？它是最大的体验改进，但会略动 `invitation-booking.ts` 的标记。
- 条目 8（请求模式是否展示忙闲）是隐私取舍：展示得越多，越容易让受邀者猜出你的日程。建议保持现状。
- 条目 4、5、7 是否值得做，取决于你对“第一次打开链接的感受”有多在意。
